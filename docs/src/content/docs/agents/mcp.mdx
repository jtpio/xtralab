xtralab runs a [Model Context Protocol](https://modelcontextprotocol.io)
(MCP) server inside JupyterLab, from
[`jupyter-server-mcp`](https://github.com/jupyter-ai-contrib/jupyter-server-mcp).
An agent that connects to it can run JupyterLab commands: for example, open
files, run notebook cells, and read notebooks.

## Install the plugin for Claude Code

The xtralab plugin registers the MCP server with Claude Code and installs the
[agent skills](../skills/).

<Steps>

1. Install [uv](https://docs.astral.sh/uv/). The plugin starts the MCP proxy
   with `uvx`.

2. Add the marketplace and install the plugin:

   ```bash
   claude plugin marketplace add jtpio/xtralab
   claude plugin install xtralab@xtralab
   ```

3. Start xtralab, then start a new Claude Code session in the same folder.
   The agent loads the `jupyter` server when the session starts.

</Steps>

The proxy finds the xtralab server from the folder of the session.

| xtralab runs in | Start the agent in                                              |
| --------------- | --------------------------------------------------------------- |
| A browser tab   | An xtralab terminal, or a different terminal in the same folder |
| The desktop app | An xtralab terminal                                             |

## Register the server manually

Use this procedure for the other agents, or when uv is not installed.

<Steps>

1. Open a terminal in xtralab.

2. Run the command for your agent:

   <Tabs syncKey="agent">
     <TabItem label="Claude Code">
       ```bash
       claude mcp add jupyter -- jupyter-server-mcp-proxy
       ```
     </TabItem>
     <TabItem label="Codex">
       ```bash
       codex mcp add jupyter -- jupyter-server-mcp-proxy
       ```
     </TabItem>
     <TabItem label="GitHub Copilot CLI">
       ```bash
       copilot mcp add jupyter -- jupyter-server-mcp-proxy
       ```
     </TabItem>
   </Tabs>

3. Start a new agent session. The agent loads the `jupyter` server when the
   session starts.

</Steps>

Register the server one time for each agent. The registration continues to
work after JupyterLab restarts.

The [launcher](../../features/launcher/#connect-agents-to-jupyterlab) shows
the same commands for the installed agents, with a **Copy** button.

:::note
Run the command in an xtralab terminal. The `jupyter-server-mcp-proxy` command
then gets the environment of the server and finds the running server. You do
not need to give a port.
:::

:::caution
For Claude Code, use the plugin or the manual registration, not the two
together. With the two together, the agent gets each tool two times.
:::

## Other agents

Goose, OpenCode, Kiro, Mistral Vibe, and Antigravity do not have an
`mcp add` command. Add a stdio MCP server to the configuration of the agent,
with the command `jupyter-server-mcp-proxy`. See the
[`jupyter-server-mcp` README](https://github.com/jupyter-ai-contrib/jupyter-server-mcp)
for other clients.

## Tools

| Tool                | Description                                           |
| ------------------- | ----------------------------------------------------- |
| `list_all_commands` | Lists the JupyterLab commands, with an optional query |
| `execute_command`   | Runs a JupyterLab command with arguments              |

The tools come from
[`jupyterlab-commands-toolkit`](https://github.com/jupyter-ai-contrib/jupyterlab-commands-toolkit).
The [guided-code-walkthrough skill](../skills/) uses them to drive the app.
